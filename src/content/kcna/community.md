# Working in the cloud native community

Kubernetes is built in public. Knowing how the community works helps you read decisions, find authoritative answers and contribute without guessing.

## How the ecosystem is organized

The **Cloud Native Computing Foundation (CNCF)** hosts projects and provides neutral governance. Projects have maintainers, contributor guides, release processes and maturity stages.

Kubernetes itself has **Special Interest Groups (SIGs)** and **Working Groups** focused on areas such as networking, scheduling, security and docs. **Technical Advisory Groups (TAGs)** in the CNCF look across projects at topics such as security, observability and runtime.

Enhancements flow through **Kubernetes Enhancement Proposals (KEPs)**. A KEP captures the problem, design, risks, graduation criteria and implementation plan. Reading a KEP is often the fastest way to understand why a feature exists.

## Finding authoritative information

Prefer sources in this order:

1. The official CNCF curriculum and Linux Foundation certification page for exam scope.
2. Kubernetes documentation for behavior and APIs.
3. Kubernetes release notes for version changes.
4. Project documentation and KEPs for implementation details.
5. Community discussion for context, not as the final authority.

Exam dumps are prohibited, unreliable and a poor way to learn. The exam rewards understanding and hands-on fluency, not memorized answers.

## Contributing without writing code

Open source needs more than code:

- improve documentation
- triage issues
- reproduce bugs with minimal examples
- review proposals
- translate content
- speak or write about what you learned

A good first contribution is small, specific and respectful of the project's process. Read `CONTRIBUTING.md` and the code of conduct before opening a pull request.

## A sustainable learning routine

- Read one release note or KEP each week.
- Re-run a lab from memory; compare against the docs.
- Keep a personal "why" journal for commands and design choices.
- Teach one concept to another student.
- Schedule practice exams, then review every wrong answer.

> **Exam lens.** You are not expected to know every CNCF project. You are expected to reason about categories, tradeoffs and the official scope. When in doubt, return to the curriculum.

## What comes next

KCNA builds the conceptual foundation. CKA adds operational depth. After CKA, paths such as CKS (security) or CKAD (application development) extend the same mental model in different directions.

The certification is a milestone, not the skill. The durable outcome is being able to explain, operate and debug the system in front of you.
